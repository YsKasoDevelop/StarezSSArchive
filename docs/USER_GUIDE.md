# スタレゾ SS アーカイブ かんたん説明書

本アプリは非公式ファンツールです。ゲームの権利者とは提携・承認関係がありません。この公開版の説明書にはゲーム画像を使用していません。

## 初回の準備

1. 配布ZIPをダウンロードして「すべて展開」します。
2. 展開先の `StarezSSArchive.exe` をダブルクリックします。EXEだけを別の場所へ移さないでください。
3. 利用条件を確認して同意した後、「同意してセットアップ」を押します。AI処理用の公式配布物を自動取得・検証します。
4. 初回設定画面で監視先・原本保存先・バックアップ保存先を確認し、「保存して開始」を押します。

.NETの手動インストールやAIファイルの手作業での配置は不要です。初回のみインターネット接続が必要です。取得に失敗した場合は接続を確認して再試行できます。閉じるボタンでキャンセルできます。AIファイルは `%LOCALAPPDATA%\StarezSSArchive\engine-20220424` に保存します。画像処理はPC内で行い、写真を送信しません。取得元: https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.5.0

## 設定と使い方

初回設定を保存するとタスクトレイに常駐して監視を開始します。以後はタスクトレイのアイコンを右クリックし「設定」を開いて変更できます。監視先・一括処理先・原本保存先・バックアップ保存先を指定します。一括処理先は初期状態で監視先（SSフォルダ）と同じです。監視先・一括処理先と、原本保存先・バックアップ保存先が重ならないようにしてください。保存時には各フォルダを作成できるか、テストファイルを書き込めるかも確認します。

監視先と一括処理先の初期値は `%USERPROFILE%\AppData\LocalLow\bokura\StarASIA\OriginalPhoto` です。原本とバックアップの初期保存先はピクチャ内の `StarASIA`、それがなく `StarASIA_STEAM` がある場合はそちらの配下です。既存の設定は維持されます。

PNGの書き込み完了後に処理が始まります。内部4倍超解像後、元と同じピクセル寸法で保存します。初期状態では処理前の画像を設定した `original` 保存先に保持し、元のフォルダには処理後の同名画像を置きます。「オリジナルファイルを残さない」をONにした場合は、原本保存を行わず、処理結果が完成してから元画像を置換します。失敗時は元画像を残します。監視先または一括処理先のPNGが100枚を超えると、処理中のフォルダから古い画像を `backup` 保存先へ退避します。

TTAは初期値OFFです。ONにすると処理時間が増えます。完了／エラー通知と「オリジナルファイルを残さない」も初期値OFFです。原本を残さない設定では、処理成功後に元画像を置き換えるため、元に戻すための原本は作られません。AIは細い模様や輪郭を変える場合があり、失われた情報を正確に復元する保証はありません。

設定画面の「保存して一括処理」を押すと、一括処理先の直下にあるPNGを調べ、未処理の画像だけを順番に処理します。原本保存がONの場合は `original` 保存先に同名ファイルがない画像、原本保存がOFFの場合は処理済み記録に一致しない画像を未処理と判定します。サブフォルダは対象外です。一括処理先を変更した場合も、設定を保存してから処理を開始します。

処理中はタスクトレイのメニューとアイコンのツールチップに監視状態、処理中のファイル名、待機件数が表示されます。「直近の処理」には成功／失敗件数が残ります。通知をONにすると、処理単位が完了したときに完了通知、失敗時にエラー通知が表示されます。完了通知をクリックすると結果画像をエクスプローラーで選択し、エラー通知をクリックするとログを開きます。「一時停止」で新しい処理を止め、「再開」で停止中に作成・更新されたPNGだけを確認します。レタッチOFF時は新たな画像処理を停止します。「終了」は処理中の画像があれば最大30秒待ちます。設定でWindowsログオン時の自動起動も変更できます。

設定を変更すると、変更前に処理待ちになっていた画像を完了してから新しい設定へ切り替えます。切り替え中も変更前の監視先を受け付け、切り替え中に追加・更新されたPNGを切り替え後に確認します。切り替え後の監視先も切り替え開始時刻以降に追加・更新されたPNGを確認します。処理待ちの画像は保存枚数の整理からも保護されます。

監視フォルダの監視エラーが発生した場合は、自動的に監視を再接続します。監視開始後に作成・更新されたPNGを再確認します。再接続に失敗しても、1秒、2秒、5秒、10秒、30秒を目安に間隔を延ばしながら再試行します。再接続中は、通知設定がONなら一度通知し、試行状況をログで知らせます。

## 処理できない場合

- 配布ZIPをすべて展開し、ファイル一式が揃っているか確認します。
- 初回セットアップと初回設定が完了しているか、GitHubへの接続が制限されていないか確認します。
- Vulkan対応GPUとドライバーが必要です。
- 監視先、レタッチON、PNG保存完了を確認します。
- ログは `%LOCALAPPDATA%\StarezSSArchive\app.log`、設定は同じ場所の `settings.json` です。「オリジナルファイルを残さない」の処理済み記録は `processed.json` に保存されます。設定の保存前のバックアップは `settings.json.bak`、破損した設定ファイルの退避先は同じフォルダ内の `.corrupt-...` 付きファイルです。
